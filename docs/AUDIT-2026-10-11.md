# Codex compatibility audit - October 11, 2026

Scope: inspect the existing project, make it globally usable in Codex across
workspaces, exercise its major components, and identify worthwhile improvements.
Baseline: `6aa44be` on `main`.
The discovery pass used 100 sequential questions in the Codex plugin/skill
evaluation pattern; this report records the actionable findings rather than the
full question transcript.

## Findings and changes

| Area | Finding | Result |
|---|---|---|
| Packaging | Only a Claude manifest and marketplace existed | Added a Codex compatibility manifest and local marketplace |
| Global use | The first setup scoped QA to one checkout | Bundle a global server; each filesystem call requires its target project's absolute path; remove the project-only configuration |
| Commands | Claude slash commands were not Codex skills | Added native run, status, resume and cache skills |
| Delegation | Instructions required Claude Task, named subagents and Claude model/permission settings | Codex roles use available native delegation and honor host/project rules |
| Hooks | Raw subagent events were written outside the metadata folder expected by resume | Codex uses explicit state transitions and file-copy snapshots; legacy hooks are disabled in its profile |
| Recovery | Legacy Git stash checkpoint creation removes working changes | New snapshot helper preserves working files, records missing files, bounds restore to the active step, and keeps run history |
| MCP shutdown | Closing stdin on Windows left the server running | Fixed the EOF marker; subprocess handshake and clean exit tested |
| Test discovery | Universal default globs caused pytest/unittest invocation failures | Use framework defaults; expand requested pytest globs; adapt unittest's filename filter |
| Project configuration | QA loaded configuration from server cwd and mutated cached config between calls | Load fresh configuration for the requested project |
| Relative paths | Test generation and regression baselines resolved relative to server cwd | Resolve both within the requested project |
| Regression tracking | Default unittest and pytest text paths omitted passing names | Preserve names and normalize pytest failure IDs; pass-to-fail baseline comparison tested |
| Jest | Filtering used the flag removed in Jest 30; parallel mode used an invalid worker value | Use stable glob-based `testMatch` and Jest's default parallel behavior |
| Generated tests | Default pytest stubs could pass without assertions and existing tests could be overwritten | Generate skipped stubs and refuse existing-file overwrite |
| PRD claims | Keyword matching was described as behavioral verification | Tool description and Codex workflow state its actual limitation |
| Completion | Legacy review demanded zero issues regardless of scope | Codex requires requested behavior and concrete checks; optional improvements do not trigger repair loops |

## Verification evidence

- All four Codex skill packages pass `quick_validate.py`.
- The running desktop runtime (`0.162.0-alpha.17.2`) reads the package, lists the
  four namespaced skills, and reports the local plugin installed and enabled.
- `codex debug prompt-input` includes all four installed skills. The loader
  selects the native global QA configuration instead of the legacy MCP file.
- `python -m unittest discover -s tests -v`: 13 passing checks, no skips in the
  tested environment (Python 3.10.11, with pytest and coverage installed).
- Real temporary projects exercised unittest and pytest passing/failing results,
  pytest glob selection, per-project configuration, named baseline regressions,
  source generation, PRD keyword analysis, aggregation, and Python coverage.
- MCP stdio initialization, all seven tool declarations, ping, and EOF exit pass
  from a project path containing spaces. All six functional handlers were also
  exercised directly with isolated inputs.
- One global MCP process selects two separate temporary projects, reports their
  different test results correctly, and rejects omitted or relative targets.
- Real Jest 30, Mocha 11 and nyc 17 fixtures: each framework correctly reported
  one passing and one deliberately failing test; explicit filtering worked;
  coverage measured the fixture's source at 100%. These are fixture results,
  not a claim of 100% coverage of MAKER itself.
- State tests cover initialization, resume after pause, completion gating,
  preservation of pre-existing edits, restoration of an interrupted step,
  removal of newly created step files, preservation of unrelated files,
  rejection of corrupt snapshots, and retention of previous completed runs.

The old `codex` on PATH is version 0.23.0. A second stale exported executable was
also present. Validation used the executable of the running desktop process;
the user's general CLI configuration and default model were not replaced.
The local MAKER marketplace/plugin is installed globally. Its bundled QA server
selects the project per call. The initially added project-only `maker-qa`
configuration was removed; no workspace is baked into the global configuration.

## Strengths retained

1. Separate planning, implementation and validation responsibilities.
2. Bounded task decomposition and explicit expected outputs.
3. Four reusable test-framework adapters.
4. Structured QA results suitable for tools and reports.
5. Configurable project test commands and hooks.
6. Coverage and named regression reporting.
7. A small stdio health-check entry point.
8. Working-directory validation around project access.
9. Reusable decomposition examples and schemas.
10. Plain files, Python/Node helpers and an MIT license, making the project portable.

## Remaining limits and useful improvements

1. **Measure real task reliability.** Package discovery, QA fixtures and checkpoint
   tests do not prove an end-to-end model-driven implementation will succeed.
   The next useful trial is a small real feature with stated acceptance criteria,
   interruption/resume, and independent review. Record time, agent calls and
   failures before claiming reliability or cost gains from decomposition/voting.
2. **Add a small CI matrix.** Run these checks on supported Python versions and
   Linux as well as Windows; include pinned JavaScript fixtures. This pass ran
   Windows locally. Cross-platform runtime behavior remains unverified.
3. **Consider the official MCP SDK when transport work is needed.** The current
   server implements protocol handling itself. Its sequential dispatch cannot
   consume a cancellation notification while a handler is running, and timeout
   signaling does not forcibly stop project subprocesses. This was inspected,
   not stress-tested here; a transport rewrite was not needed for this port.
4. **Improve legacy-only behavior separately.** The Claude profile retains its
   original prompts and hooks. Its stash recovery and broad keyword triggers
   should be reconsidered before relying on that profile. This pass did not run
   Claude Code or claim that its lifecycle integration was repaired.
5. **Improve evidence quality where needed.** The PRD checker remains a keyword
   heuristic, generated tests remain scaffolds, and test adapters have differing
   skip/error reporting and discovery conventions. In particular, unittest uses
   its first configured filename pattern. None should be treated as exhaustive
   verification of a feature.

No model API integration, remote publishing, commits, or pushes were added.
The installed skills remain agent instructions: the state helper records supplied
evidence and does not independently enforce the truth of a model's report.
